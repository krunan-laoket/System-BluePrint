# การปรับตามบริบทไทย

อ่านหลังรู้ว่าผู้ใช้ทำงานในบริบทไหน เนื้อหานี้บอกว่าต้อง **ถามเพิ่มอะไร** และ **ใส่อะไรลงไฟล์ไหน** คำถามเพิ่มแต่ละข้อมีป้าย *หัวข้อ: ...* บอกว่าให้ถามรวมไปกับหัวข้อไหนของการสัมภาษณ์ ฉบับย่อถามเฉพาะข้อที่มี [ย่อ] ส่วนเรื่องข้อมูลส่วนบุคคล (PDPA) ด้านล่างถามทุกโหมดเมื่อระบบเก็บข้อมูลบุคคล (ฉบับย่อถามเฉพาะ: ข้อมูลอ่อนไหว ผู้เยาว์ และส่งข้อมูลออกนอกประเทศ) ไม่ใช่คำปรึกษาทางกฎหมาย กฎระเบียบเปลี่ยนได้ ให้เขียนในไฟล์ 08 ว่า "ควรตรวจสอบฉบับล่าสุดกับฝ่ายกฎหมายหรือหน่วยงานที่เกี่ยวข้อง" เสมอ และห้ามสรุปว่า "ระบบนี้ต้องปฏิบัติตามกฎหมาย X" ถ้าไม่แน่ใจ ให้เขียนว่า "อาจเกี่ยวข้อง" แล้วบันทึกเป็น [รอตัดสินใจ] ให้ฝ่ายกฎหมายยืนยัน

## ใช้กับทุกบริบท: กฎหมายคุ้มครองข้อมูลส่วนบุคคล (PDPA)

ถ้าระบบเก็บข้อมูลของบุคคลที่ระบุตัวตนได้ ให้ถามและบันทึกใน 05 และ 08:

- เก็บข้อมูลอะไร เพื่ออะไร (วัตถุประสงค์ต้องชัด)
- ใช้ฐานทางกฎหมายอะไร: ขอความยินยอม / จำเป็นเพื่อทำสัญญา / หน้าที่ตามกฎหมาย / ประโยชน์อันชอบธรรม / ภารกิจของรัฐ ถ้าผู้ใช้ไม่ทราบ ให้ [รอตัดสินใจ] แล้วแนะนำให้ถามฝ่ายกฎหมาย
- ข้อมูลอ่อนไหวมีไหม (สุขภาพ ศาสนา เชื้อชาติ ประวัติอาชญากรรม ข้อมูลชีวภาพ ฯลฯ)
- ข้อมูลของผู้เยาว์มีไหม (ต้องมีผู้ปกครองให้ความยินยอมในหลายกรณี)
- ส่งข้อมูลออกนอกประเทศหรือไม่ (รวมถึงเก็บบนบริการคลาวด์ต่างประเทศ)
- ใช้ผู้ให้บริการภายนอกประมวลผลข้อมูลหรือไม่ (ต้องมีข้อตกลงระหว่างกัน)
- ผู้ใช้ขอดู แก้ไข ลบข้อมูลตัวเองได้อย่างไร (สิทธิของเจ้าของข้อมูล)
- ระยะเวลาเก็บข้อมูล และแจ้งเหตุเมื่อข้อมูลรั่วไหลภายในกี่ชั่วโมง ใครรับผิดชอบ (ให้ผู้ใช้หรือฝ่ายกฎหมายยืนยันกรอบเวลาตามกฎหมายฉบับล่าสุด ห้ามเขียนตัวเลขเองเป็นข้อเท็จจริง)
- มีบันทึกรายการกิจกรรมการประมวลผลข้อมูลส่วนบุคคล (ROPA) หรือไม่ ใครดูแล
- กิจกรรมที่อาจมีความเสี่ยงสูงต่อเจ้าของข้อมูล (ข้อมูลอ่อนไหวจำนวนมาก ติดตามพฤติกรรม ใช้ข้อมูลใบหน้า) ควรประเมินผลกระทบ (DPIA) หรือไม่ ให้ [รอตัดสินใจ] ให้ DPO หรือฝ่ายกฎหมายยืนยัน
- ถ้าเป็นเว็บไซต์หรือแอปที่ใช้คุกกี้หรือเครื่องมือติดตาม: ต้องมีแบนเนอร์และนโยบายคุกกี้หรือไม่
- ผู้ที่มีสิทธิ์รับเรื่องร้องเรียนและช่องทางติดต่อเจ้าหน้าที่คุ้มครองข้อมูลส่วนบุคคล

ผลที่ต้องปรากฏในเอกสาร: ไฟล์ 05 ทำเครื่องหมายข้อมูลส่วนบุคคลทุกรายการ, ไฟล์ 08 มีรายการภาระด้านข้อมูลส่วนบุคคล, ไฟล์ 06 ความปลอดภัยสอดคล้องกัน, ไฟล์ 12 มีเกณฑ์เรื่องนโยบายความเป็นส่วนตัวและการขอความยินยอม

## ใช้กับทุกบริบท: ข้อกฎหมายอื่นที่ควรถามว่าเกี่ยวข้องหรือไม่

| เรื่อง | ถามเมื่อ | ผลต่อเอกสาร |
|---|---|---|
| พ.ร.บ.ว่าด้วยการกระทำความผิดเกี่ยวกับคอมพิวเตอร์ (การเก็บข้อมูลจราจรทางคอมพิวเตอร์ตามที่กฎหมายกำหนด) | ระบบให้บริการแก่บุคคลภายนอก มีผู้ใช้ส่งข้อมูลเข้ามา | ไฟล์ 06 ประวัติการใช้งาน, ไฟล์ 08 |
| พ.ร.บ.ธุรกรรมทางอิเล็กทรอนิกส์ | มีลายเซ็นอิเล็กทรอนิกส์ สัญญาออนไลน์ เอกสารอิเล็กทรอนิกส์ | ไฟล์ 07, 08 |
| กฎหมายภาษีและบัญชี (ใบกำกับภาษี ใบรับ หัก ณ ที่จ่าย) | มีการออกเอกสารทางการเงิน | ไฟล์ 03, 05 (ต้องเก็บเอกสารตามระยะเวลา) |
| กฎหมายคุ้มครองผู้บริโภค | ขายของหรือบริการแก่ประชาชน | ไฟล์ 04 ขั้นตอนคืนสินค้า/ร้องเรียน |
| ลิขสิทธิ์และทรัพย์สินทางปัญญา | จ้างทำ ใช้เนื้อหาหรือภาพของผู้อื่น ทำร่วมกับหน่วยงานอื่น | ไฟล์ 08 ใครเป็นเจ้าของผลงาน |
| กฎระเบียบเฉพาะธุรกิจ (การเงิน ประกัน สุขภาพ การศึกษา) | ธุรกิจอยู่ภายใต้หน่วยงานกำกับ | ไฟล์ 08 [รอตัดสินใจ] ให้ฝ่ายกฎหมายระบุ |
| ใบกำกับภาษีอิเล็กทรอนิกส์และใบรับอิเล็กทรอนิกส์ (e-Tax Invoice & e-Receipt) ตามแนวทางของกรมสรรพากร | ออกเอกสารภาษีผ่านระบบ | ไฟล์ 03, 07, 08 (ถามฝ่ายบัญชีว่าต้องใช้หรือไม่) |
| มาตรฐานการเข้าถึงเนื้อหาเว็บ (เช่น WCAG) ที่หน่วยงานรัฐหรือผู้ว่าจ้างกำหนด | เว็บหรือแอปให้บริการประชาชน | ไฟล์ 06, 12 |
| พ.ร.บ.ข้อมูลข่าวสารของราชการ และกฎหมายที่เกี่ยวกับข้อมูลเปิดภาครัฐ | หน่วยงานรัฐ มีข้อมูลที่ประชาชนขอดูได้ | ไฟล์ 05, 08 |
| การบริหารงานและการให้บริการภาครัฐผ่านระบบดิจิทัล (กฎหมายและมาตรฐานของ สพร./DGA ที่เกี่ยวข้อง) | หน่วยงานรัฐให้บริการหรือแลกเปลี่ยนข้อมูลทางดิจิทัล | ไฟล์ 07, 08 ให้หน่วยงานยืนยันฉบับที่ใช้ |

ตารางนี้เป็นรายการให้ **ถามว่าเกี่ยวข้องหรือไม่** ไม่ใช่รายการที่สรุปว่าต้องปฏิบัติ ชื่อกฎหมาย ปี และมาตราต้องให้ผู้ใช้หรือฝ่ายกฎหมายยืนยัน

## ใช้กับทุกบริบท: ข้อมูลและรูปแบบเฉพาะไทย

ถามและบันทึกใน 05 ถ้าเกี่ยวข้อง: ปี พ.ศ./ค.ศ., เลขบัตรประชาชน 13 หลักและการตรวจความถูกต้อง, ที่อยู่แบบไทย (ตำบล/อำเภอ/จังหวัด/รหัสไปรษณีย์), คำนำหน้าชื่อ, ชื่อสองภาษา, การเรียงและค้นหาภาษาไทย, การออกเอกสารภาษาไทยที่ต้องพิมพ์ (ฟอนต์ที่หน่วยงานกำหนด), วันหยุดราชการที่กระทบการนับวัน

## บริบท A: สถานศึกษา (วิทยาลัย มหาวิทยาลัย)

ถามเพิ่ม:

1. **ประเภทงาน**: โครงงานรายวิชา / ปริญญานิพนธ์ / วิทยานิพนธ์ / ระบบใช้งานจริงในสถานศึกษา (เช่น ระบบทะเบียน ห้องสมุด) หรือทั้งสองอย่าง (โครงงานที่จะนำไปใช้จริง) — *หัวข้อ: เป้าหมาย* [ย่อ]
2. **ระดับ**: ปวช. / ปวส. / ปริญญาตรี / บัณฑิตศึกษา (กำหนดความลึกของเอกสารและรูปแบบรูปเล่ม) — *หัวข้อ: เป้าหมาย*
3. **รูปเล่มและกำหนดส่ง**: สถาบันมีแม่แบบรูปเล่มและกำหนดการสอบ/ส่งหรือไม่ ใครเป็นที่ปรึกษา — *หัวข้อ: ข้อจำกัด*
4. **การเก็บข้อมูลจากคน** (แบบสอบถาม สัมภาษณ์ ทดลองใช้ระบบกับผู้ใช้จริง): ต้องผ่านคณะกรรมการจริยธรรมการวิจัยหรือไม่ มีใบยินยอมของผู้เข้าร่วมหรือไม่ — *หัวข้อ: ข้อจำกัด*
5. **เจ้าของผลงาน**: ใครเป็นเจ้าของ (ผู้พัฒนา สถาบัน หน่วยงานที่ร่วมทำ) และจะนำไปใช้หรือเผยแพร่ต่อหรือไม่ — *หัวข้อ: ข้อจำกัด*
6. **ผู้ใช้จริง**: ถ้าเป็นระบบที่ใช้จริง ผู้ใช้คือนักศึกษา อาจารย์ เจ้าหน้าที่ หรือบุคคลภายนอก และข้อมูลนักศึกษาอยู่ภายใต้ระเบียบสถาบันอย่างไร — *หัวข้อ: ผู้ใช้* [ย่อ]
7. **ระบบกลางและมาตรฐานการศึกษา**: ต้องเชื่อมกับระบบกลางของหน่วยงานต้นสังกัด (เช่น ระบบข้อมูลสารสนเทศด้านการศึกษา) หรือเอกสารประกันคุณภาพที่ต้องส่งหรือไม่ ถ้าไม่ทราบให้ [รอตัดสินใจ] ไม่ระบุชื่อระบบเอง — *หัวข้อ: การเชื่อมต่อ*
8. **ข้อมูลผู้เรียน**: ข้อมูลผู้เรียนที่เป็นผู้เยาว์ ผลการเรียน หรือข้อมูลสุขภาพ มีระเบียบการเข้าถึงอย่างไร ใครเป็นเจ้าของข้อมูล — *หัวข้อ: ข้อมูล* [ย่อ]

ผลต่อเอกสาร:
- ไฟล์ 01 เพิ่มหัวข้อ "เหตุผลและความสำคัญของโครงงาน" และ "วัตถุประสงค์" ในรูปประโยคที่นำไปใช้เป็นบทที่ 1 ได้ (บอกใน README ว่านำไปใช้ต่อได้)
- ไฟล์ 12 เพิ่มเกณฑ์การประเมิน เช่น แบบประเมินความพึงพอใจของผู้ใช้ (กลุ่มตัวอย่างกี่คน เกณฑ์ผ่านเท่าไร) ถ้าผู้ใช้มี
- ไฟล์ 08 เพิ่มเรื่องจริยธรรมการวิจัย เจ้าของผลงาน และข้อจำกัดด้านเวลา (กำหนดสอบ) กับงบ (มักไม่มีหรือน้อย)
- ไฟล์ 11 ความเสี่ยงที่พบบ่อย: ผู้ใช้จริงไม่ว่างมาทดลอง ขอบเขตใหญ่เกินเวลาเรียน สมาชิกกลุ่มมีทักษะไม่เท่ากัน
- ระบุใน README ว่าเอกสารชุดนี้ไม่ใช่รูปเล่มโครงงานฉบับสมบูรณ์ ต้องนำไปเรียบเรียงตามแม่แบบของสถาบัน (บทที่ 2 ทฤษฎีและงานวิจัยที่เกี่ยวข้อง และการอ้างอิง สกิลนี้ไม่สร้าง)

## บริบท B: บริษัทเอกชน

ถามเพิ่ม:

1. **ผู้สนับสนุนและผู้ตัดสินใจ**: ใครเป็นเจ้าของงบ ใครอนุมัติ — *หัวข้อ: เป้าหมาย* [ย่อ]
2. **ใช้ภายใน หรือให้ลูกค้าภายนอกใช้**: ภายนอกมีเรื่องข้อมูลส่วนบุคคล ผู้บริโภค และความปลอดภัยเข้มกว่า — *หัวข้อ: ผู้ใช้* [ย่อ]
3. **ดำเนินการเอง หรือจ้างบริษัทภายนอก**: ถ้าจ้างภายนอก ต้องมีเอกสารสำหรับเสนอราคา/ทำสัญญา ถามว่าต้องการขอเสนอราคาจากผู้พัฒนาหลายรายหรือไม่ (ไฟล์ 15 ใช้เป็นฐานของเอกสารชี้แจงงานให้ผู้เสนอราคาทุกรายได้เหมือนกัน) — *หัวข้อ: ข้อจำกัด* [ย่อ]
4. **ธุรกิจอยู่ภายใต้หน่วยงานกำกับหรือไม่** (เช่น การเงิน ประกัน สุขภาพ โทรคมนาคม) — *หัวข้อ: ข้อจำกัด*
5. **มาตรฐานองค์กร**: มีนโยบายความปลอดภัยสารสนเทศหรือมาตรฐานที่ต้องปฏิบัติตาม (เช่น ISO 27001) ไหม มีทีมไอทีหรือฝ่ายความปลอดภัยที่ต้องตรวจก่อนใช้จริงไหม — *หัวข้อ: คุณภาพ*
6. **ภาษี/การเงิน**: ระบบเกี่ยวกับใบกำกับภาษี การหัก ณ ที่จ่าย การเงินหรือไม่ มีฝ่ายบัญชีเป็นผู้ใช้หรือไม่ — *หัวข้อ: ข้อมูล*

ผลต่อเอกสาร:
- ไฟล์ 01 เพิ่ม "ผลลัพธ์ทางธุรกิจที่คาดหวัง" (ประหยัดเท่าไร รายได้เพิ่มเท่าไร) ถ้าผู้ใช้ให้ตัวเลข
- ไฟล์ 08 เพิ่มงบ รูปแบบสัญญา (จ้างเหมา รายงวด) ถ้ามี และบทบาทฝ่ายไอที/ฝ่ายกฎหมายที่ต้องอนุมัติ
- ไฟล์ 12 ผูกเกณฑ์เสร็จกับการตรวจรับงวดงาน ถ้าจ้างภายนอก
- ไฟล์ 15 ส่วนสำหรับผู้บริหารเน้นเหตุผลทางธุรกิจ และเรื่องที่ต้องอนุมัติ

## บริบท C: หน่วยงานราชการ / รัฐวิสาหกิจ

ถามเพิ่ม:

1. **หน่วยงานและสังกัด**: ส่วนกลาง ส่วนภูมิภาค ส่วนท้องถิ่น รัฐวิสาหกิจ สถาบันการศึกษาของรัฐ (กำหนดระเบียบที่ใช้) — *หัวข้อ: เป้าหมาย*
2. **ที่มาของงบ**: งบประมาณประจำปี งบเงินรายได้ เงินกู้ งบโครงการพิเศษ และปีงบประมาณที่ต้องใช้ (เป็นตัวกำหนดเวลาตายตัว) — *หัวข้อ: ข้อจำกัด* [ย่อ]
3. **วิธีจัดหา**: จัดซื้อจัดจ้างตามกฎหมายว่าด้วยการจัดซื้อจัดจ้างและการบริหารพัสดุภาครัฐ (วิธีเฉพาะเจาะจง/คัดเลือก/ประกวดราคา) หรือพัฒนาเองภายใน การกำหนดคุณลักษณะต้องไม่ล็อกยี่ห้อหรือผู้ขายรายเดียว ซึ่งสอดคล้องกับหลักการของสกิลนี้ที่ไม่ระบุเทคโนโลยีเป็นคำตอบ — *หัวข้อ: ข้อจำกัด* [ย่อ]
4. **คณะกรรมการ**: ใครเป็นคณะกรรมการกำหนดขอบเขตงาน (TOR) ใครเป็นกรรมการตรวจรับ — *หัวข้อ: เกณฑ์เสร็จ*
5. **มาตรฐานภาครัฐดิจิทัล**: ต้องสอดคล้องกับมาตรฐานของสำนักงานพัฒนารัฐบาลดิจิทัล (สพร. หรือ DGA) เช่น กรอบสถาปัตยกรรมองค์กร มาตรฐานข้อมูลภาครัฐ การเชื่อมโยงข้อมูลกับหน่วยงานอื่น หรือการใช้ระบบกลางของรัฐ (เช่น บัญชีผู้ใช้กลาง ระบบเชื่อมโยงข้อมูลกลาง) หรือไม่ — *หัวข้อ: การเชื่อมต่อ*
6. **ความมั่นคงปลอดภัยไซเบอร์**: หน่วยงานเป็นโครงสร้างพื้นฐานสำคัญทางสารสนเทศตามกฎหมายว่าด้วยการรักษาความมั่นคงปลอดภัยไซเบอร์หรือไม่ มีมาตรฐานหรือแนวปฏิบัติของหน่วยงานกำกับดูแลที่ต้องทำตามหรือไม่ — *หัวข้อ: คุณภาพ*
7. **การเก็บรักษาเอกสาร**: ข้อมูลเป็นเอกสารราชการที่มีระเบียบสารบรรณและอายุการเก็บเฉพาะหรือไม่ — *หัวข้อ: ข้อมูล*
8. **ความโปร่งใส**: มีข้อมูลที่ต้องเปิดเผยต่อสาธารณะ (ข้อมูลเปิดภาครัฐ) หรือไม่ — *หัวข้อ: ข้อมูล*
9. **ที่ตั้งของข้อมูล**: มีระเบียบเรื่องการเก็บข้อมูลบนคลาวด์หรือเซิร์ฟเวอร์ของหน่วยงานหรือไม่ มีนโยบายใช้ศูนย์ข้อมูลหรือคลาวด์กลางของรัฐ (เช่น GDCC) หรือไม่ ถ้าไม่ทราบให้ [รอตัดสินใจ] — *หัวข้อ: ข้อจำกัด* [ย่อ]
10. **เหตุผลความจำเป็นและการขออนุมัติโครงการ**: ต้องจัดทำเอกสารขออนุมัติหลักการหรือแผนงานโครงการตามระเบียบของหน่วยงานหรือไม่ และต้องผ่านคณะกรรมการดิจิทัลหรือคณะกรรมการไอทีของหน่วยงานก่อนหรือไม่ (ไฟล์ 01 ส่วนเหตุผลความจำเป็นใช้เป็นฐานได้) — *หัวข้อ: เป้าหมาย*
11. **การกำหนดราคากลางและการประเมินความคุ้มค่า**: ถามว่าต้องมีหรือไม่ และใครเป็นผู้จัดทำ (สกิลนี้ไม่คำนวณราคากลาง) — *หัวข้อ: ข้อจำกัด*
12. **การเชื่อมโยงข้อมูลและบัญชีผู้ใช้กลาง**: ต้องใช้ระบบยืนยันตัวตนกลางของรัฐ (เช่น Digital ID / ThaID) หรือระบบแลกเปลี่ยนข้อมูลกลางหรือไม่ — *หัวข้อ: การเชื่อมต่อ* [ย่อ]
13. **การรับประกันและการบำรุงรักษา**: โครงการภาครัฐมักกำหนดระยะรับประกันและบำรุงรักษารายปีใน TOR ให้ถามค่าที่หน่วยงานนิยมใช้ และบันทึกในไฟล์ 08 หัวข้อการส่งมอบและหลังใช้งาน — *หัวข้อ: ข้อจำกัด*

ผลต่อเอกสาร:
- ไฟล์ 08 มีส่วน "ระเบียบและกฎหมายภาครัฐที่เกี่ยวข้อง" ที่หน่วยงานต้องยืนยัน และบันทึกคำถามที่ยังไม่ทราบเป็น [รอตัดสินใจ] ไม่ตอบแทน
- ไฟล์ 12 เกณฑ์เสร็จผูกกับการตรวจรับโดยคณะกรรมการ และเกณฑ์ต้องวัดได้เพราะใช้อ้างอิงในการตรวจรับ
- ไฟล์ 15 ระบุว่าเอกสารชุดนี้เป็น **ฐานข้อมูลสำหรับร่าง TOR** ไม่ใช่ TOR ฉบับสมบูรณ์ (TOR ต้องจัดรูปแบบและตรวจโดยเจ้าหน้าที่พัสดุและคณะกรรมการตามระเบียบ) และเตือนว่าคุณลักษณะที่เขียนต้องไม่เอื้อรายใดรายหนึ่ง
- ไฟล์ 11 ความเสี่ยงที่พบบ่อย: ขั้นตอนจัดซื้อจัดจ้างใช้เวลานานกว่ากำหนด งบถูกตัดหรือเลื่อน ผู้บริหารเปลี่ยนนโยบายเมื่อเปลี่ยนตัว ผู้ดูแลระบบหลังส่งมอบไม่ชัดเจน

## ถ้าผู้ใช้ไม่แน่ใจว่าตัวเองอยู่บริบทไหน หรืออยู่หลายบริบท

เช่น มหาวิทยาลัยของรัฐ (ทั้งสถานศึกษาและหน่วยงานรัฐ) ให้ใช้ทั้งสองชุดคำถาม ระบุในไฟล์ 08 ว่าเกี่ยวข้องกับทั้งสองบริบท และปล่อยให้ผู้ใช้ตัดสินว่าข้อไหนใช้
