# ระบบยืมอุปกรณ์ห้องปฏิบัติการ

ชุดเอกสารความต้องการของระบบยืมอุปกรณ์ห้องปฏิบัติการคอมพิวเตอร์ จัดทำเพื่อยืนยันขอบเขตกับอาจารย์ดูแลห้องก่อนเริ่มพัฒนา (ตัวอย่างนี้ใช้ข้อมูลสมมติทั้งหมด)

ทะเบียน `blueprint.json` ระบุโหมดและชื่อไฟล์จริง ใช้ตรวจโครงสร้าง ไม่ใช่การรับรองความถูกต้องทางธุรกิจ

| รายการ | ค่า |
|---|---|
| ฉบับ | 0.1 (ร่างแรก) |
| วันที่จัดทำ | 21 ตุลาคม 2569 |
| โหมดเอกสาร | โหมดขอบเขตธุรกิจและเตรียม TOR |
| สถานะเอกสาร | ผ่านการตรวจโครงสร้างและรีวิวเนื้อหาภายในแล้ว รอยืนยันประเด็นกับอาจารย์ดูแลห้อง |
| สถานะตัวระบบ | ยังไม่เริ่มพัฒนา |

## ระบบนี้ทำอะไร
1. นักศึกษาค้นหาอุปกรณ์และจองล่วงหน้าผ่านมือถือ
2. เจ้าหน้าที่ส่งมอบอุปกรณ์ที่เคาน์เตอร์ ระบบจำว่าใครยืมและต้องคืนเมื่อใด
3. ก่อนครบกำหนด ระบบเตือนนักศึกษา และเมื่อเลยกำหนด รายการขึ้นเป็นค้างคืน
4. เจ้าหน้าที่รับคืนและบันทึกสภาพ อาจารย์ดูรายการค้างคืนได้ตลอด

## โครงสร้างชุดเอกสาร
```text
README.md                          ทางเข้าหลัก (ไฟล์นี้)
blueprint.json                     ทะเบียนโหมดและชื่อไฟล์
docs/00-source.md                  ข้อมูลต้นทางและคำตอบสัมภาษณ์
docs/01-overview.md                ภาพรวม เป้าหมาย ขอบเขต คุณภาพ และกลุ่มข้อมูล
docs/02-features.md                รายการฟีเจอร์และสิทธิ์
docs/03-flows.md                   ลำดับการทำงาน สถานะ และค่าที่ตั้งได้
docs/04-screens.md                 รายการหน้าจอ
docs/05-decisions.md               ประเด็นที่ต้องตัดสินใจ
docs/06-development-plan.md        แผนพัฒนา
docs/07-acceptance.md              เกณฑ์ตรวจรับและเมทริกซ์สอบกลับ
plans/scope-confirmation-plan.md   แผนประชุมยืนยันขอบเขต
```

## เริ่มอ่านที่ไหนตามบทบาท
| ถ้าคุณคือ | เริ่มอ่านที่ | แล้วอ่านต่อที่ |
|---|---|---|
| อาจารย์ดูแลห้อง | `docs/01-overview.md` | `docs/05-decisions.md` |
| เจ้าหน้าที่ห้องปฏิบัติการ | `docs/02-features.md` | `docs/03-flows.md` และ `docs/04-screens.md` |
| ทีมพัฒนา | `docs/03-flows.md` | `docs/07-acceptance.md` และ `docs/06-development-plan.md` |

## ข้อควรรู้ก่อนอ่าน
- **ที่มาและความชัดเจนของข้อมูล:** ปัญหา ผู้ใช้ และฟีเจอร์หลักมาจากคำตอบของทีมนักศึกษา ค่าที่ทีมเสนอติดเครื่องหมาย (รอยืนยัน) และอธิบายใน `docs/05-decisions.md` เรื่องที่กระทบความพร้อมมากที่สุดคือช่องทางแจ้งเตือนและอายุการเก็บข้อมูลนักศึกษา
- **การควบคุมการเปลี่ยนแปลง:** เมื่อรับรองฉบับนี้แล้ว การเพิ่มหรือแก้ความต้องการให้แก้ที่ `docs/02-features.md` และ `docs/03-flows.md` ก่อน แล้วประเมินผลกระทบต่อเวลาและไฟล์อื่น
