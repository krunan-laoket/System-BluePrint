# ประเด็นที่ต้องตัดสินใจและบันทึกการตัดสินใจ (Decision Log)

ผู้มีอำนาจตัดสินใจคืออาจารย์ดูแลห้อง ทีมนักศึกษาตอบ "ใช้ตามที่เสนอ" ได้เพื่อให้ทำงานต่อ แต่ยืนยันแทนอาจารย์ไม่ได้

สถานะของประเด็นมี 3 แบบ:
- **ตัดสินใจแล้ว** — ผู้มีอำนาจตัดสินใจยืนยันข้อสรุปแล้ว
- **ใช้ค่าที่เสนอไปก่อน รอยืนยันกับลูกค้า** — ทีมใช้ค่าที่แนะนำไปในเอกสารเพื่อให้ทำงานต่อได้ แต่รอผู้มีอำนาจยืนยัน
- **รอตัดสินใจ** — ยังไม่มีข้อมูลเพียงพอ ต้องได้รับคำตอบจากผู้เกี่ยวข้องก่อน

## สรุปประเด็นทั้งหมด
| # | ประเด็น | สถานะ |
|---|---|---|
| 1 | ระยะเวลายืมสูงสุดและเวลารอรับอุปกรณ์ | ใช้ค่าที่เสนอไปก่อน รอยืนยันกับลูกค้า |
| 2 | ช่องทางแจ้งเตือนก่อนครบกำหนดคืน | รอตัดสินใจ |
| 3 | อายุการเก็บข้อมูลผู้ยืมและประวัติการยืม | รอตัดสินใจ |
| 4 | การอบรมและระยะรับประกันผลงาน | ใช้ค่าที่เสนอไปก่อน รอยืนยันกับลูกค้า |
| 5 | เป้าหมายตัวเลขที่ทีมเสนอ | ใช้ค่าที่เสนอไปก่อน รอยืนยันกับลูกค้า |
| 6 | จำนวนวันจองล่วงหน้าสูงสุด | ตัดสินใจแล้ว |
| 7 | ฟีเจอร์และค่าที่ทีมเสนอเพิ่ม | ใช้ค่าที่เสนอไปก่อน รอยืนยันกับลูกค้า |

**ประเด็นที่ต้องปิดก่อนเริ่มพัฒนา:** ประเด็นที่ 1 และประเด็นที่ 2 (กระทบสถานะและการแจ้งเตือน)
**ประเด็นที่ต้องปิดก่อนเปิดใช้งานจริง:** ประเด็นที่ 3, 4, 5 และ 7

## 1. ระยะเวลายืมสูงสุดและเวลารอรับอุปกรณ์
**สถานะ:** ใช้ค่าที่เสนอไปก่อน รอยืนยันกับลูกค้า (21 ตุลาคม 2569)
**ที่มา:** ต้นทางไม่ได้ระบุ ทีมเสนอระหว่างสัมภาษณ์ (00-source.md ข้อ 3)
**ทางเลือกและผลกระทบ**
- **ทางเลือก ก:** ยืม 7 วัน รอรับถึงเวลาปิดห้องของวันจอง — *ข้อดี:* อุปกรณ์หมุนเวียนเร็ว / *ข้อเสียและผลต่องบหรือเวลา:* นักศึกษาที่ทำงานยาวต้องยืมใหม่
- **ทางเลือก ข:** ยืม 14 วัน รอรับ 2 วัน — *ข้อดี:* สะดวกกับงานโครงงาน / *ข้อเสียและผลต่องบหรือเวลา:* อุปกรณ์ว่างน้อยลงช่วงต้นภาคเรียน
**ค่าที่ใช้ในเอกสาร / คำแนะนำของทีม:** ทางเลือก ก เพราะอุปกรณ์มีจำกัดและผู้ใช้ประมาณ 300 คน
**ส่วนงานที่ยังทำไม่ได้:** ไม่มี ร่างต่อได้ด้วยค่าที่เสนอ
**ผู้มีอำนาจตัดสินใจและคำถามที่ต้องถาม:** อาจารย์ดูแลห้อง — "ให้ยืมได้นานสุดกี่วัน และถ้าจองแล้วไม่มารับ ให้รอถึงเมื่อไร"
**ผลกระทบเมื่อคำตอบเปลี่ยน:** 03-flows.md หัวข้อค่าที่ตั้งได้ในระบบ และกรณีอื่นของ Flow 1, 02-features.md ข้อ 3.1, 07-acceptance.md ข้อ 1.1

## 2. ช่องทางแจ้งเตือนก่อนครบกำหนดคืน
**สถานะ:** รอตัดสินใจ (21 ตุลาคม 2569)
**ที่มา:** ผู้ใช้ตอบว่า "ยังไม่รู้ว่าต้องแจ้งเตือนทางไหน" (00-source.md ข้อ 1)
**ทางเลือกและผลกระทบ**
- **ทางเลือก ก:** อีเมลมหาวิทยาลัย — *ข้อดี:* ไม่มีค่าใช้จ่าย ใช้ข้อมูลที่เก็บอยู่แล้ว / *ข้อเสียและผลต่องบหรือเวลา:* นักศึกษาอาจไม่เปิดอ่าน
- **ทางเลือก ข:** แอปแชตที่นักศึกษาใช้ — *ข้อดี:* อ่านเร็ว / *ข้อเสียและผลต่องบหรือเวลา:* ต้องสมัครบริการ มีโควตาข้อความ และต้องเก็บข้อมูลบัญชีเพิ่ม
**ค่าที่ใช้ในเอกสาร / คำแนะนำของทีม:** แนะนำอีเมลมหาวิทยาลัย แต่ยังไม่ใส่ในเอกสารเพราะกระทบข้อมูลส่วนบุคคลและภาระของห้อง
**ส่วนงานที่ยังทำไม่ได้:** ออกแบบข้อความแจ้งเตือนและการตรวจรับ 07-acceptance.md ข้อ 1.3
**ผู้มีอำนาจตัดสินใจและคำถามที่ต้องถาม:** อาจารย์ดูแลห้อง — "จะให้แจ้งเตือนนักศึกษาทางอีเมลมหาวิทยาลัยหรือทางแอปแชต"
**ผลกระทบเมื่อคำตอบเปลี่ยน:** 02-features.md ข้อ 3.2, Flow 2, 01-overview.md ข้อ 7

## 3. อายุการเก็บข้อมูลผู้ยืมและประวัติการยืม
**สถานะ:** รอตัดสินใจ (21 ตุลาคม 2569)
**ที่มา:** ต้นทางไม่ได้ระบุ เป็นเรื่องข้อมูลส่วนบุคคลที่ทีมตัดสินแทนไม่ได้
**ทางเลือกและผลกระทบ**
- **ทางเลือก ก:** เก็บจนนักศึกษาพ้นสภาพ — *ข้อดี:* ตามประวัติได้ครบ / *ข้อเสียและผลต่องบหรือเวลา:* เก็บข้อมูลนานเกินจำเป็น
- **ทางเลือก ข:** เก็บ 1 ปีหลังคืนอุปกรณ์ — *ข้อดี:* ข้อมูลน้อยลง / *ข้อเสียและผลต่องบหรือเวลา:* ต้องมีงานลบข้อมูลตามรอบ
**ค่าที่ใช้ในเอกสาร / คำแนะนำของทีม:** ยังไม่เลือก ให้เจ้าหน้าที่คุ้มครองข้อมูลของคณะให้ความเห็นก่อน
**ส่วนงานที่ยังทำไม่ได้:** กำหนดงานลบข้อมูลและการตรวจรับด้านข้อมูลส่วนบุคคล
**ผู้มีอำนาจตัดสินใจและคำถามที่ต้องถาม:** อาจารย์ดูแลห้องร่วมกับเจ้าหน้าที่คุ้มครองข้อมูลของคณะ — "ต้องเก็บประวัติการยืมพร้อมชื่อนักศึกษาไว้นานเท่าไร"
**ผลกระทบเมื่อคำตอบเปลี่ยน:** 01-overview.md ข้อ 7, 07-acceptance.md ข้อ 3

## 4. การอบรมและระยะรับประกันผลงาน
**สถานะ:** ใช้ค่าที่เสนอไปก่อน รอยืนยันกับลูกค้า (21 ตุลาคม 2569)
**ที่มา:** ต้นทางไม่ได้ระบุ ทีมเสนอตามกำลังของทีมนักศึกษา
**ทางเลือกและผลกระทบ**
- **ทางเลือก ก:** อบรมครึ่งวัน รับประกันจนจบภาคเรียนแรก — *ข้อดี:* ทีมทำได้จริงก่อนจบการศึกษา / *ข้อเสียและผลต่องบหรือเวลา:* หลังจากนั้นคณะต้องหาผู้ดูแลเอง
- **ทางเลือก ข:** รับประกัน 1 ปี — *ข้อดี:* ห้องมั่นใจกว่า / *ข้อเสียและผลต่องบหรือเวลา:* ทีมอาจจบการศึกษาก่อนครบกำหนด
**ค่าที่ใช้ในเอกสาร / คำแนะนำของทีม:** ทางเลือก ก และให้ระบุผู้ดูแลต่อจากฝั่งคณะ
**ส่วนงานที่ยังทำไม่ได้:** ไม่มี
**ผู้มีอำนาจตัดสินใจและคำถามที่ต้องถาม:** อาจารย์ดูแลห้อง — "หลังภาคเรียนแรก ใครจะดูแลระบบต่อ"
**ผลกระทบเมื่อคำตอบเปลี่ยน:** 01-overview.md ข้อ 4.2, 06-development-plan.md ข้อ 2

## 5. เป้าหมายตัวเลขที่ทีมเสนอ
**สถานะ:** ใช้ค่าที่เสนอไปก่อน รอยืนยันกับลูกค้า (21 ตุลาคม 2569)
**ที่มา:** ผู้ใช้ให้ค่าปัจจุบัน (สูญหายประมาณ 12 ชิ้นต่อภาคเรียน) ส่วนค่าเป้าหมายทีมเสนอ
**ทางเลือกและผลกระทบ**
- **ทางเลือก ก:** สูญหายไม่เกิน 3 ชิ้น รองรับ 50 คนพร้อมกัน หน้าค้นหาไม่เกิน 3 วินาที — *ข้อดี:* วัดได้ในภาคเรียนแรก / *ข้อเสียและผลต่องบหรือเวลา:* ต้องจัดทดสอบจำลองผู้ใช้
- **ทางเลือก ข:** ไม่กำหนดตัวเลขคุณภาพ — *ข้อดี:* งานน้อยลง / *ข้อเสียและผลต่องบหรือเวลา:* ตรวจรับไม่ได้ว่าระบบพร้อม
**ค่าที่ใช้ในเอกสาร / คำแนะนำของทีม:** ทางเลือก ก
**ส่วนงานที่ยังทำไม่ได้:** ไม่มี
**ผู้มีอำนาจตัดสินใจและคำถามที่ต้องถาม:** อาจารย์ดูแลห้อง — "ยอมรับเป้าหมายสูญหายไม่เกิน 3 ชิ้นต่อภาคเรียนหรือไม่"
**ผลกระทบเมื่อคำตอบเปลี่ยน:** 01-overview.md ข้อ 1 และข้อ 6, 07-acceptance.md ข้อ 3

## 6. จำนวนวันจองล่วงหน้าสูงสุด
**สถานะ:** ตัดสินใจแล้ว (21 ตุลาคม 2569)
**ที่มา:** ข้อความของอาจารย์ดูแลห้องที่ทีมส่งต่อ (00-source.md ข้อ 2)
**ผู้ยืนยัน:** อาจารย์ดูแลห้อง
**วันที่ยืนยัน:** 21 ตุลาคม 2569
**หลักฐานยืนยัน:** ข้อความในกลุ่มแชตของโครงงาน "จองล่วงหน้าได้ไม่เกิน 3 วัน"
**ทางเลือกและผลกระทบ**
- **ทางเลือก ก:** 3 วัน — *ข้อดี:* ไม่มีใครกันอุปกรณ์ไว้นาน / *ข้อเสียและผลต่องบหรือเวลา:* ไม่มี
**ค่าที่ใช้ในเอกสาร / คำแนะนำของทีม:** 3 วัน ตามที่อาจารย์กำหนด
**ส่วนงานที่ยังทำไม่ได้:** ไม่มี
**ผู้มีอำนาจตัดสินใจและคำถามที่ต้องถาม:** อาจารย์ดูแลห้อง — ตอบแล้ว
**ผลกระทบเมื่อคำตอบเปลี่ยน:** 02-features.md ข้อ 1.1.2, Flow 1

## 7. ฟีเจอร์และค่าที่ทีมเสนอเพิ่ม
**สถานะ:** ใช้ค่าที่เสนอไปก่อน รอยืนยันกับลูกค้า (21 ตุลาคม 2569)
**ที่มา:** ต้นทางไม่ได้ระบุ ทีมเสนอเพื่อไม่ให้อุปกรณ์ถูกจองค้างและลดการคืนช้า
**ทางเลือกและผลกระทบ**
- **ทางเลือก ก:** ให้นักศึกษายกเลิกการจองเองได้ และแจ้งเตือนก่อนครบกำหนด 1 วัน — *ข้อดี:* อุปกรณ์ว่างเร็วขึ้น และคืนตรงเวลามากขึ้น / *ข้อเสียและผลต่องบหรือเวลา:* เพิ่มงานพัฒนาประมาณ 1 สัปดาห์ (ประมาณการของทีม)
- **ทางเลือก ข:** ไม่มีทั้งสองอย่างในรอบแรก — *ข้อดี:* งานน้อยลง / *ข้อเสียและผลต่องบหรือเวลา:* นักศึกษาต้องมาแจ้งยกเลิกที่เคาน์เตอร์
**ค่าที่ใช้ในเอกสาร / คำแนะนำของทีม:** ทางเลือก ก
**ส่วนงานที่ยังทำไม่ได้:** ไม่มี
**ผู้มีอำนาจตัดสินใจและคำถามที่ต้องถาม:** อาจารย์ดูแลห้อง — "ให้นักศึกษายกเลิกการจองเองได้ และแจ้งเตือนก่อนครบกำหนดคืน 1 วัน ตามที่ทีมเสนอหรือไม่"
**ผลกระทบเมื่อคำตอบเปลี่ยน:** 02-features.md ข้อ 1.1.3 และข้อ 3.2, 03-flows.md หัวข้อค่าที่ตั้งได้ในระบบ, Flow 1 และ Flow 2
