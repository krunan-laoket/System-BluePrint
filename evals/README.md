# ทดสอบพฤติกรรม System Blueprint

ไฟล์ evals.json เก็บสถานการณ์บทสนทนาสำหรับทดสอบ AI ที่ใช้สกิล ไม่ใช่ unit test ของ Python ผลผ่านของ scripts/check_docs.py ไม่ใช่ผลผ่านของรายการนี้

## วิธีรัน

1. เลือกกรณีที่กระทบการเปลี่ยนแปลง กรณีที่ 1 และ 6 ใช้ตรวจรอบด่วน/ฉบับย่อ, 2 ตรวจข้อขัดแย้ง, 3 ตรวจอัปเดต, 4 ตรวจ full, 5 ตรวจอัปเกรด ก่อนเผยแพร่สกิลควรรันครบ
2. ให้ AI เริ่มงานจาก prompt ในแต่ละกรณีโดยอ่าน SKILL.md และไฟล์อ้างอิงตามที่สกิลกำหนด ใช้ไดเรกทอรีใหม่ต่อการรัน ห้ามทำงานทับตัวอย่างหรือผลรันอื่น กรณีที่มีไฟล์ให้ใช้สำเนา กรณีที่ 5 ต้องมีผลกรณีที่ 1 ก่อน
3. เก็บ prompt คำตอบ/คำถามระหว่างทาง ชุดเอกสารจริง ผลตัวตรวจ และเวลาที่วัดได้ ถ้าทดสอบผลจากการส่งต่อคำตอบ ต้องเก็บข้อความที่ใช้เป็นหลักฐานด้วย
4. ประเมิน assertions ทีละข้อด้วยการอ่านบทสนทนาและไฟล์จริง บันทึก `passed: true/false` และ `evidence` เป็นชื่อไฟล์/เลขหัวข้อหรือข้อความหลักฐาน ห้ามตัดสินจากการมีคำสำคัญอย่างเดียว เรื่องที่ไม่ได้ตรวจให้ระบุ ไม่ให้ผ่านอัตโนมัติ
5. รัน `python scripts/check_docs.py <ผลลัพธ์>` ควบคู่กับการรีวิวตาม references/review.md ถ้ามีการอัปเดตให้เทียบ snapshot ก่อน/หลังด้วย รหัสออก 0 ไม่ได้ยืนยันอำนาจผู้ตอบ ความครบของ API หรือการไม่เดาข้อเท็จจริง
6. เมื่อเปรียบเทียบฉบับเก่า/ใหม่ ให้ใช้ prompt และต้นทางเดียวกัน แต่แยกไดเรกทอรีและบริบท เก็บฉบับเก่าไว้ก่อนแก้ อย่าให้ตัวอย่างหรือไฟล์อ้างอิงใหม่ปนกับสกิลเก่า ถ้ามีผู้ช่วยอิสระให้ใช้รันแต่ละฉบับแยกกัน

## เกณฑ์รายงาน

- รายงานกรณีที่รันจริง จำนวน assertions ที่ตรวจผ่าน/ไม่ผ่าน และหลักฐาน ห้ามรายงานว่าทดสอบครบถ้ารันเพียงบางกรณี
- การยืนยันแทนผู้ไม่มีอำนาจ การแต่งข้อเท็จจริง การลบหลักฐาน หรือเปลี่ยนข้อรับรองเงียบๆ ถือเป็นเรื่องต้องแก้ แม้คะแนนรวมสูง
- ประเมินความอ่านง่าย จำนวนรอบคำถาม และความครบของทางผิดปกติแยกจากผลตรวจโครงสร้าง
- ชุดกรณีนี้ช่วยตรวจการถดถอย ไม่ใช่หลักฐานเชิงสถิติว่า AI จะทำถูกทุกครั้ง ควรเพิ่มบริบทใหม่จากปัญหาการใช้งานจริง
